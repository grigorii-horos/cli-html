# cli-html Architecture

This document describes the internal architecture of cli-html for contributors
and maintainers.

────────────────────────────────────────────────────────────────────────────────

## Overview

cli-html takes HTML (or Markdown → HTML) and renders it to styled terminal
output using ANSI escape codes via chalk [https://github.com/chalk/chalk].

The rendering pipeline:

  1 Input (HTML string or file)
  2   │
  3   ▼
  4 parse5 (HTML parser)
  5   │ AST
  6   ▼
  7 render-tag.js (recursive renderer)
  8   │
  9   ├── tag registry (lib/tags.js)
 10   │     └── tag handlers (lib/tags/*.js)
 11   │
 12   ├── theme (lib/utils/get-theme.js)
 13   │     └── config.yaml (base) + user config (override)
 14   │
 15   └── output (ANSI-colored string)

For Markdown input, an additional step runs first:

 1 Markdown string
 2   │
 3   ▼
 4 markdown-it (+ plugins)
 5   │ HTML string
 6   ▼
 7 (same pipeline as above)

## Core Modules

### lib/utils/render-tag.js

The heart of the renderer. Recursively walks the parse5 AST.

 • Uses WeakMap for caching (auto-GC when nodes are no longer referenced)
 • MAX_DEPTH = 100 prevents infinite recursion on malformed HTML
 • Context object flows through the tree: { theme, lineWidth, asciiMode, depth }

 1 // Simplified render-tag logic
 2 function renderNode(node, context) {
 3   if (context.depth > MAX_DEPTH) return null;
 4 
 5   const handler = tagRegistry[node.nodeName];
 6   if (!handler) return renderChildren(node, context);
 7 
 8   return handler(node, { ...context, depth: context.depth + 1 });
 9 }

### lib/utils/get-theme.js

Merges base config (config.yaml) with user overrides.

 1 export function getTheme(customInput = {}) {
 2   return deepMerge(BASE_THEME, customInput);
 3 }

Theme values are plain strings ("red bold", "bgBlue white"). No chalk functions
in the theme object.

### lib/core/color.js

Applies chalk-string colors to text.

 1 applyColor(spec, text)            // spec is a chalk-string or null
 2 applyThemeColor(custom, theme, text) // custom attr override → theme → no
 ↳ color

### lib/core/attr.js

Reads data-cli-* attributes via dot-path notation.

 1 getAttr(tag, 'prefix.marker')  // reads data-cli-prefix-marker
 2 getAttr(tag, 'border.color')   // reads data-cli-border-color

Returns null when attribute absent. Always returns strings (not booleans).
Boolean attributes: check getAttr(tag, 'key') === 'true'.

## Tag Handler Pattern

Every tag handler has the same signature:

 1 export const myTag = (tag, context) => {
 2   // Returns one of:
 3   // { type: 'inline', value, pre: null, post: null, nodeName }
 4   // { type: 'block', value, marginTop?, marginBottom? }
 5   // null (suppress output)
 6 };

For block elements, use blockTag() from lib/tag-helpers/block-tag.js. For inline
elements, use inlineTag() from lib/tag-helpers/inline-tag.js.

 1 import inlineTag from '../tag-helpers/inline-tag.js';
 2 import { getAttr } from '../core/attr.js';
 3 import { applyThemeColor } from '../core/color.js';
 4 
 5 export const time = inlineTag((value, tag, context) => {
 6   const theme = context.theme.time ?? {};
 7   return applyThemeColor(getAttr(tag, 'color'), theme.color, value);
 8 });

## Configuration System

### Two-level config

 1. Base config (config.yaml) — default values for every theme property
 2. User config — platform-specific file, merged over base at startup

User config locations:

 • Linux: ~/.config/cli-html/config.yaml
 • macOS: ~/Library/Preferences/cli-html/config.yaml
 • Windows: %LOCALAPPDATA%\cli-html\Config\config.yaml

### Three-level override per element

Priority (high → low):

 1. data-cli-* attribute on the HTML element
 2. User config (~/.config/cli-html/config.yaml)
 3. Base config (config.yaml)

In code:

 1 const color = getAttr(tag, 'color') ?? context.theme.myTag?.color;

## Adding a New Tag

 1. Create lib/tags/your-tag.js
 2. Import and register in lib/tags.js
 3. Add defaults to config.yaml
 4. Add TypeScript types to index.d.ts
 5. Add example to examples/html/tags/your-tag.html
 6. Add tests to test/rendering/config-override.test.js

See CLAUDE.md for the complete tag authoring guide.

## Performance

 • WeakMap caching in render-tag.js: cached render results per node
 • LRU eviction (max 1000 entries) for string length calculations
 • Theme is computed once at startup, not per-render
 • registerCache() system for coordinated cache management

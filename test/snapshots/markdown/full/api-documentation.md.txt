## Authentication

All API requests require authentication using an API key or JWT token.

### API Key Authentication

Include your API key in the Authorization header:

 1 curl -H "Authorization: Bearer YOUR_API_KEY" \
 2      https://api.example.com/users

### OAuth 2.0

For OAuth 2.0 authentication, follow these steps:

 1. Obtain authorization code
 2. Exchange code for access token
 3. Use access token in requests

│ Important
│ 
│ Never expose your API keys in client-side code or public repositories.

## Endpoints

### Users

#### List Users

Get a paginated list of users.

Endpoint: GET /users

Query Parameters:


┌───────────┬─────────┬──────────┬────────────────────────────────────────┐
│ Parameter │ Type    │ Required │ Description                            │
├───────────┼─────────┼──────────┼────────────────────────────────────────┤
│ page      │ integer │ No       │ Page number (default: 1)               │
├───────────┼─────────┼──────────┼────────────────────────────────────────┤
│ limit     │ integer │ No       │ Items per page (default: 20, max: 100) │
├───────────┼─────────┼──────────┼────────────────────────────────────────┤
│ sort      │ string  │ No       │ Sort field (name, email, created_at)   │
├───────────┼─────────┼──────────┼────────────────────────────────────────┤
│ order     │ string  │ No       │ Sort order (asc, desc)                 │
└───────────┴─────────┴──────────┴────────────────────────────────────────┘

Response:

#### Get User

Retrieve a specific user by ID.

Endpoint: GET /users/{id}

Path Parameters:


┌───────────┬─────────┬──────────┬─────────────┐
│ Parameter │ Type    │ Required │ Description │
├───────────┼─────────┼──────────┼─────────────┤
│ id        │ integer │ Yes      │ User ID     │
└───────────┴─────────┴──────────┴─────────────┘

Response:

 1 {
 2   "id": 1,
 3   "name": "John Doe",
 4   "email": "john@example.com",
 5   "role": "admin",
 6   "created_at": "2025-01-15T10:30:00Z",
 7   "updated_at": "2025-12-01T14:20:00Z"
 8 }

#### Create User

Create a new user account.

Endpoint: POST /users

Request Body:

 1 {
 2   "name": "Jane Smith",
 3   "email": "jane@example.com",
 4   "password": "secure_password_123",
 5   "role": "user"
 6 }

Validation Rules:

 • [✓] name - Required, 2-100 characters
 • [✓] email - Required, valid email format
 • [✓] password - Required, minimum 8 characters
 • [✓] role - Optional, one of: admin, user, guest

Response: 201 Created

 1 {
 2   "id": 151,
 3   "name": "Jane Smith",
 4   "email": "jane@example.com",
 5   "role": "user",
 6   "created_at": "2025-12-01T15:00:00Z"
 7 }

#### Update User

Update an existing user.

Endpoint: PUT /users/{id}

Request Body:

 1 {
 2   "name": "Jane Doe",
 3   "email": "jane.doe@example.com"
 4 }

Response: 200 OK

│ Tip
│ 
│ Use PATCH instead of PUT for partial updates to improve performance.

#### Delete User

Delete a user account.

Endpoint: DELETE /users/{id}

Response: 204 No Content

│ Warning
│ 
│ This action is permanent and cannot be undone. Consider soft deletion for
│ production systems.

### Authentication Endpoints

#### Login

Authenticate and receive an access token.

Endpoint: POST /auth/login

Request Body:

 1 {
 2   "email": "john@example.com",
 3   "password": "secure_password"
 4 }

Response:

 1 {
 2   "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
 3   "token_type": "Bearer",
 4   "expires_in": 3600
 5 }

#### Logout

Invalidate the current access token.

Endpoint: POST /auth/logout

Response: 200 OK

#### Refresh Token

Get a new access token using a refresh token.

Endpoint: POST /auth/refresh

### Common Error Codes

AUTHENTICATION_FAILED ::

  Invalid credentials provided

INVALID_TOKEN ::

  Access token is invalid or expired

RESOURCE_NOT_FOUND ::

  Requested resource does not exist

VALIDATION_ERROR ::

  Request data failed validation

RATE_LIMIT_EXCEEDED ::

  Too many requests in a short time
